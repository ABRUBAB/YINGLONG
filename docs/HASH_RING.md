# Hash Ring specification (v1)

The Hash Ring is the visual fingerprint of a sealed mandate: 64 ticks and nine arcs drawn from the
delegation hash. It proves **hash identity, not mandate correctness**: two mandates that differ in any
field have visibly different rings, but a ring says nothing about whether the rules are good.

Two independent implementations must agree bit for bit:

| Implementation | Location |
|---|---|
| TypeScript (reference) | `packages/ui/src/hash-ring/geometry.ts`, `hashRingGeometry(H)` |
| Python twin | `tools/verify-py` (`yinglong verify` prints the ring as SVG and as an ASCII strip) |
| Agent service | `hashRing` in every MandateView (`docs/API.md`), cross-checked by the web app |

## Input

`H` = the 32-byte EIP-712 **delegation hash** the DelegationManager accepts for the mandate's
delegation (`getDelegationHash`, the struct hash; no second hash). Accepted as a `0x`-prefixed
64-digit hex string or 32 raw bytes. Anything else is an error.

## Coordinates

- Ring radius `R` (golden files use `R = 1`).
- Angles in degrees, screen coordinates (x right, y down): `-90` is 12 o'clock and angles increase
  **clockwise**.

## Ticks (64)

For `i` in `0..63`:

```
n_i      = H[i >> 1] >> 4     if i is even   (high nibble)
         = H[i >> 1] & 0x0f   if i is odd    (low nibble)
angleDeg = -90 + i * 5.625
r0       = 0.8 * R
r1       = r0 + (0.04 + 0.01 * n_i) * R
```

Tick `i` is the radial segment from `r0` to `r1` at `angleDeg`. Lengths run from `0.04 R`
(nibble 0) to `0.19 R` (nibble 15).

## Arcs (9)

```
K = keccak256(H)                        (32 bytes; Ethereum keccak, not SHA3-256)
for j in 0..8:
  startDeg = -90 + (K[j] * 360) / 256
  sweepDeg = 8 + (K[j + 9] mod 32)      (8 to 39 degrees)
  r        = (0.7 - 0.025 * j) * R      (0.70 R down to 0.50 R)
```

Arc `j` runs clockwise from `startDeg` for `sweepDeg` at radius `r`.

## Revoked state

A revoked mandate omits ticks `i in {62, 63, 0, 1}` (a gap at 12 o'clock) and draws every
remaining tick in the ash colour. Arcs are unchanged.

## Floating point

Compute every value with **the exact expression order above** (for example
`r0 + (0.04 + 0.01 * n) * R`, and `(K[j] * 360) / 256`), in IEEE-754 binary64. Python and
JavaScript then produce identical doubles. Compare with an absolute tolerance of `1e-12` if a
language cannot guarantee the same order.

## Output shape

```
hashRingGeometry(H, { R = 1, revoked = false }) ->
{
  ticks: [{ i, angleDeg, r0, r1 }],        // 64 entries (60 when revoked), ascending i
  arcs:  [{ j, startDeg, sweepDeg, r }]    // 9 entries, ascending j
}
```

The service's `hashRing.ticks[]` additionally carries `nibble`; the web app ignores it and compares
`angleDeg`, `r0`, `r1` after dividing by the service's `R` (derived from `r0 / 0.8`).

## Golden vectors

Generated by `pnpm --filter @yinglong/ui golden` into `packages/ui/test/golden/`:

| File | H | revoked |
|---|---|---|
| `zero.json` | 32 zero bytes | no |
| `ones.json` | 32 bytes of `0xff` | no |
| `phrase.json` | `keccak256(utf8("YINGLONG Hash Ring golden vector 3"))` | no |
| `phrase-revoked.json` | same as `phrase.json` | yes |

Each file records `H`, `K = keccak256(H)`, `R`, `revoked` and the full `geometry`. A twin passes
when its output equals `geometry` for all four files (tests: `packages/ui/test/hash-ring.test.ts`).

## Property

Two independent uniform hashes differ in each tick length with probability 15/16, so the number of
differing tick lengths is Binomial(64, 15/16) with mean 60; fewer than 16 has probability below
1e-50. The tests assert at least 16 differing ticks for 5,000 random pairs and for 2,000 one-bit
changes of a mandate's encoding (hashed with keccak256).

## Rendering (web)

`packages/ui/src/hash-ring/hash-ring.tsx` draws each tick as a unit line transformed by
`rotate(angleDeg) translateX(r0) scaleX(r1 - r0)`, so a new hash morphs tick lengths in place (the
"one word, new seal" moment). Phases: `draft` (muted, dashed base), `holding` (press-and-hold
progress ring), `sealed` (chrome, ticks drawn in), `revoked` (ash, gap). The caption under every large
ring reads: "The ring proves hash identity, not mandate correctness."
